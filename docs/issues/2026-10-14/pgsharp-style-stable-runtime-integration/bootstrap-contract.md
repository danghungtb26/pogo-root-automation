**Scope:** Pokémon GO 0.433.0; Android 28+; `arm64-v8a` và `x86_64`/translation. Đây là working contract của [plan](checklists/00-overview.md), chưa phải bằng chứng live.

## Migration invariant

1. Một session/process, một companion reader/reactor, một native gameplay owner. Broker tạo identity từ attach, không từ PID đơn lẻ; process chết phải drop volatile state.
2. Early status có thể báo attach/error khi game build chưa biết. Không ép `buildFingerprint` giả vào `RUNTIME_READY`; Kotlin phải phân biệt transport session với strong game identity.
3. Core lifecycle chỉ chuyển qua gate có bằng chứng; connected/ACK/library mapping/poll không cấp mutation. `IL2CPP_INITIALIZED` phải phát **sau** original init return.
4. Mọi bước migration giữ buildable. Trước khi game gate được verify, pre-live capability rỗng. Không dual-run scheduler/poll path làm fallback.

## Dependency và rollback boundary

- Sau broker/status: có thể quan sát attach, nhưng mọi game capability vẫn đóng.
- Sau loader/core split: nếu core FD/manifest/ABI hoặc lifecycle gate lỗi, báo phase/error, không chạy gameplay.
- Chỉ gỡ monolith/poll-primary sau startup matrix trên `BlueStacks Air 1` đạt. Rollback dùng revision/artifact baseline và **một** runtime owner, không khởi chạy hai đường song song.
- Các section REA dossier, FD feasibility và wire schema chi tiết sẽ được cập nhật tại T-002–T-004. Unknown không được thay bằng tên symbol/RVA suy đoán.

## FD loader feasibility (T-003 chọn cơ chế; T-010/T-020 chờ live)

Source SDK cho thấy app `minSdk = 28`, native build `ANDROID_PLATFORM=android-28`. Zygisk API vendored cho `connectCompanion()` trong pre-specialize và `exemptFd()`; companion ABI-aware. NDK 28.2 `android/dlext.h` khai báo `ANDROID_DLEXT_USE_LIBRARY_FD`, `android_dlopen_ext()` và nói filename vẫn dùng nhận diện library. Header cũng ghi `ANDROID_DLEXT_USE_NAMESPACE` chỉ internal, không có NDK API để chọn namespace. NDK 27.1 override ghi trong plan **không có trên máy này**; NDK 28.2 có sẵn.

**Lựa chọn implementation:** companion mở core đúng ABI từ Magisk module, kiểm manifest/digest rồi truyền read-only FD qua `SCM_RIGHTS` trên socket `connectCompanion()` ngay trong pre-specialize. Loader nhận/exempt FD, kiểm lại manifest/digest, rồi ở post-specialize dùng `android_dlopen_ext("libpogo_runtime_core.so", RTLD_NOW | RTLD_LOCAL, ...)` với `ANDROID_DLEXT_USE_LIBRARY_FD`. Core chỉ link system libraries (cần kiểm `DT_NEEDED` tại build) để tránh dependency namespace ngoài NDK; không dùng `ANDROID_DLEXT_USE_NAMESPACE` internal. FD có một owner sau `recvmsg`, đóng sau `dlopen` thành công/thất bại; companion đóng bản của mình sau `sendmsg`. Không sửa core artifact của process đang chạy: digest pin theo ZIP và chỉ có hiệu lực với process mới.

Lựa chọn này có cơ sở ở NDK 28.2/Zygisk API nhưng **chưa chứng minh** linker namespace/SELinux/lifetime thực tế trên `BlueStacks Air 1`. T-010 và T-020 phải kiểm postcondition trên target; nếu fail thì `FAILED_CORE_LOAD`/capability rỗng. Không dùng `/data/adb/...` làm command queue hoặc nạp core từ mạng.

**Checkpoint implementation 2026-10-14:** `core_handoff.h`/`core_sha256.h` kiểm canonical manifest, ELF machine, size/hash và dùng `SCM_RIGHTS` trên socket companion; `loader_module.inc` nhận/exempt FD trước specialize, kiểm lại rồi nạp bằng `ANDROID_DLEXT_USE_LIBRARY_FD` sau specialize. `core_entry.cpp` nhận socket ownership và phát `CORE_LOADED`. ARM64 cài `LibraryLifecycleObserver` synchronously: thành công phát `LOADER_OBSERVER_ACTIVE`, successful return của `android_dlopen_ext` cho `libil2cpp.so` cài exact-prologue `il2cpp_init` hook trước khi trả control, worker phát `IL2CPP_LIBRARY_SEEN` và chỉ sau original init success mới phát `IL2CPP_INITIALIZED`. ABI/translation không hỗ trợ, linker owner/prologue lạ, library đã mapped hoặc event miss đều về FAILED; trước `LIVE_READY` capability rỗng. x86_64 báo `unsupported_abi`. Broker giữ snapshot FAILED khi stream đóng để controller mở muộn thấy lỗi. Native multi-ABI build và ZIP validation pass; **chưa có bằng chứng live** cho handoff/hook/phase order trên BlueStacks Air 1. Host build không phải proof của FD path hay lifecycle postcondition.

## Wire/session schema (T-004)

Đề xuất bridge protocol `4`, native internal runtime protocol `5`, frame mới `RUNTIME_BOOTSTRAP_STATUS = 12`, payload schema `1`. Mismatch protocol/marker/schema/length đóng kết nối; không downgrade im lặng. Giữ hard frame limit 4 MiB và đặt giới hạn trường nhỏ hơn mức này. `RUNTIME_READY` chỉ được phát sau khi fingerprint thực có; controller v4 không đợi frame đó để xác nhận session.

| Field của bootstrap payload | Kiểu/ràng buộc | Nguồn/ý nghĩa |
|---|---|---|
| `sessionId`, `pid`, `processName` | string ≤256 UTF-8 bytes, positive int, string ≤256 | Companion tạo khi `TARGET_ATTACHED`; tuple buộc frame vào process |
| `sequence`, `phase` | uint64 >0, enum known | Monotonic trong session; phase chỉ tiến hoặc terminal `FAILED_*` |
| `gameBuild`, `abi`, `translationLayer` | nullable UTF-8 strings ≤4096/64/64 | Build absent trước verify; ABI/translation absent cho đến khi xác định, không dùng placeholder giả |
| `recoverable`, `errorCode`, `message` | bool, nullable strings ≤256/4096 | Error code chính xác; missed init yêu cầu process restart |
| `strongIdentityVerified`, `capabilities` | bool, bounded set ≤256 entries, mỗi entry ≤256 | `false`/empty trước exact build + backend/owner gates |
| `observedAtEpochMs`, `observedAtElapsedNs` | nonnegative int64 | Freshness và replay; frame replay giữ observation time, envelope seq tăng riêng |

Broker sở hữu `CREATED`/attach session envelope và sequence trước core. Một handoff atomic chuyển quyền phase transition sang core; broker chỉ validate/cache/forward core snapshot sau đó, không tự nâng phase từ probe, ACK hay timeout. Controller frame sequence riêng để chống replay; `sequence` trong payload là phase transition sequence, không tăng khi replay cùng snapshot. Controller chỉ chấp nhận session/pid/process khớp, phase seq tăng (hoặc equal khi reconnect snapshot), monotonic freshness và exact identity cho live status/observations. `gameBuild` absent không thể thỏa `RuntimeReady.buildFingerprint` nonblank: `RuntimeBridgeClient.connect()` trả session handle từ bootstrap frame và `submitDesiredState` dùng authenticated `sessionId`.

Không dùng `RUNTIME_BOOTSTRAP_STATUS` hoặc `RUNTIME_READY` để cấp mutation. Native chỉ mở `RuntimeUiStatus.ready` khi post-init, exact build identity, main-thread/owner freshness và capability verified; lease/arm/config revision vẫn phải hợp lệ. Desired snapshot có thể được nhận sớm, nhưng apply ở gate phù hợp; CONFIG/START ACK là receipt, không là action outcome. Process mới làm session mới, xóa pending command/result, live pointer, lease và arm; Android config app-private vẫn là durable source. Companion có đúng một reactor đọc runtime stream và multiplex controller theo correlation/seq; chỉ cache snapshot cuối, không replay gameplay commands/results.
